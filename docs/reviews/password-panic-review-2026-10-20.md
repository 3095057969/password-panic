## 1. 结论

产品的核心规则引擎可完成，21 条规则与三个互动关卡能够组成一条实际通关路径。现有 8 个单元测试全部通过，但测试范围集中在纯规则函数，无法证明存档恢复、重开、异步回调、IME、动效偏好和保存失败等浏览器行为正确。

发布前应优先解决 3 个 P1 阻断项：不可信存档可直接锁局、胜利延迟回调会跨越重开、IME 合成态 Enter 被当作提交键处理。Unicode 截断和保存失败无提示同样影响数据完整性，应与前三项进入同一稳定性补丁。

本报告没有修改产品代码。PRD V2.0 把这些问题写成待实现、可验收的目标，不能据此宣称产品已经修复。

## 2. 代码评审发现

### CODE-001 [P1] 不可信存档可制造假胜利并锁定新局

- 位置：`js/game.js:181-211`、`js/game.js:204-209`、`js/game.js:338-342`、`js/game.js:1303-1315`。
- 证据：浏览器实测。
- 复现：向 `password-panic-state-v1` 写入空密码、`activeCount: 1`、`victory: true`、负数 `finishMs`、字符串 `captchaSolved: "false"` 后刷新。
- 实际：输入框被禁用；胜利弹窗显示 21/21 和 0 字符；字符串 `"false"` 经 `Boolean()` 变为 `true`；负耗时未被拒绝；界面只显示一张规则卡。
- 根因：恢复逻辑信任 `victory`，用宽松布尔转换接收非布尔值，且 `syncUI` 只建立胜利、不撤销不合法胜利。
- 期望：严格验证字段类型、范围和状态不变量；根据 21 条规则及互动状态重算胜利；不合法胜利必须降级为可继续游玩的状态。
- 关联：`FR-STATE-006`、`FR-STATE-010`、`AC-025`。

### CODE-002 [P1] 胜利弹窗延迟回调会跨越重开

- 位置：`js/game.js:56-57`、`js/game.js:341-342`、`js/game.js:1187-1223`、`js/game.js:1303-1315`。
- 证据：浏览器实测。
- 复现：在第 21 条即将通过时补上末尾 `?`，随后在 420ms 内确认重开。
- 实际：新局状态已经清空且 `victory=false`，旧局回调仍在约 420ms 后打开“胜利”弹窗，显示 0 字符并锁定页面滚动。
- 根因：胜利和恢复弹窗定时器未保存句柄；重开不清理；`showVictory()` 不校验当前局标识与 `state.victory`。
- 期望：异步回调绑定 session/generation；重开时清理所有旧局定时器；执行前再次校验胜利状态。
- 关联：`FR-ASYNC-001`、`FR-WIN-011`、`AC-026`。

### CODE-003 [P1] IME 合成态 Enter 被阻止并触发失焦

- 位置：`js/game.js:115-119`。
- 证据：合成态 KeyboardEvent 自动化复现；尚未完成 Windows、iOS 各输入法人工矩阵。
- 复现：向主输入框派发 `key="Enter"`、`isComposing=true` 的键盘事件。
- 实际：事件被 `preventDefault()`，输入框被 `blur()`。
- 风险：中文、日文等输入法确认候选时可能被当作表单提交或结束输入，破坏未提交文本。
- 期望：`event.isComposing` 或合成会话期间不拦截 Enter；在 `compositionend` 后统一规范化和校验。
- 关联：`FR-INPUT-010`、`AC-027`。

### CODE-004 [P1] 140 字符上限混用 UTF-16 与 Unicode 码点

- 位置：`index.html:159`、`js/game.js:192`。
- 证据：浏览器实测。
- 复现 A：存档密码为 139 个 `🐱` 加 `a`，刷新恢复。
- 实际 A：只保留 70 个码点，因为 `.slice(0, 140)` 按 UTF-16 码元截断。
- 复现 B：存档密码为 139 个 `a` 加 `🐱`，刷新恢复。
- 实际 B：恢复结果以孤立高代理 `55357` 结尾。
- 根因：HTML `maxlength` 与字符串 `.slice()` 均不是 PRD 声明的码点计数。
- 期望：统一使用 `Array.from(value).slice(0, 140).join("")` 等码点安全方式；禁止产生孤立代理项。
- 关联：`FR-INPUT-005`、`FR-INPUT-011`、`AC-028`。

### CODE-005 [P1] localStorage 写入失败静默丢失进度

- 位置：`js/game.js:217-224`。
- 证据：浏览器实测。
- 复现：令 `Storage.prototype.setItem` 抛出 `QuotaExceededError` 后继续输入。
- 实际：游戏可继续，但页面没有持久提示；刷新会丢失本次进度。
- 根因：异常被捕获但没有建立 UI 状态或重试结果反馈。
- 期望：显示持久、可访问的“本次进度无法保存，刷新会丢失”状态；成功保存后清除；提示需要节流，不能每次按键播报。
- 关联：`FR-STATE-011`、`AC-029`。

### CODE-006 [P2] 减少动效偏好未覆盖验证码 JavaScript 动画

- 位置：`js/game.js:983-991`；相关 CSS 约 `assets/css/styles.css:3095-3110`。
- 证据：浏览器实测。
- 复现：在 `prefers-reduced-motion: reduce` 环境提交错误验证码。
- 实际：仍执行 220ms、水平位移约 4px 的 WAAPI 摇晃。
- 期望：CSS 与 JavaScript 动效使用同一偏好判断；减少动效时保留静态错误文字和 ARIA 反馈。
- 关联：`FR-UX-006`、`AC-030`。

### CODE-007 [P2] 同一输入同时“新通过”和“回归”时公告掩盖回归

- 位置：`js/game.js:304-314`。
- 证据：浏览器实测。
- 复现：在人工注入的已解锁 12 条隔离状态中，使第 11 条首次通过，同时删除第 3 条所需符号。该注入用于隔离通知分支；自然路径可先让第 11 条因移除 `喵` 回归，再在同次编辑中恢复 `喵` 并删除唯一允许符号。
- 实际：规则卡正确显示第 3 条失败，但公告只播报“第 11 条已通过”。
- 根因：通知分支优先选择 `newlyResolved`，忽略同次变更的 `regressed`。
- 期望：回归通知优先，或合并播报通过与回归；相同消息去重。
- 关联：`FR-RULE-011—013`、`AC-031`、`AC-036`。

### CODE-008 [P2] 验证码大小写文案与实现不一致

- 位置：`js/rules.js:131`、`js/game.js:481`、`js/game.js:965-978`。
- 证据：代码检查和浏览器实测。
- 实际：文案称“区分大小写”，提交逻辑会 `trim().toUpperCase()`；小写正确答案可通过。
- 期望：V2 明确采用大小写不敏感匹配并统一文案。验证码只是游戏关卡，不是安全边界。
- 关联：`FR-CAP-004`、`AC-009`。

### CODE-009 [P2] 自动化测试未覆盖浏览器状态机

- 位置：`package.json`、`tests/rules.test.mjs`。
- 证据：测试清单检查。
- 实际：8 个测试全部通过，但仅覆盖规则表、辅助函数和在预置 `activeCount=21`/互动标记下的参考解。
- 风险：CODE-001 至 CODE-008 均不会导致现有测试失败。
- 期望：增加浏览器 E2E，覆盖真实解锁、存档迁移、重开竞态、IME、保存失败、动效偏好和移动端关键路径。
- 关联：`TEST-002`、`TEST-003`、发布门禁。

## 3. PRD V1.0 评审发现

### PRD-001 [P0] 胜利定义自相矛盾

V1 的产品流程要求所有规则通过，但 `FR-WIN-001` 写成“第 21 条通过后立即胜利”。第 21 条只验证长度恰好 42，不能代替其他规则。V2 统一为：21 条均处于通过或合法废止状态，其中第 04 条由第 13 条废止。

### PRD-002 [P0] 优先级、实现状态与路线图冲突

V1 把存档恢复问题标为 P0“需修正”，同时路线图又称产品 v1.0 已实现，并把修复排入 v1.1。V2 明确：文档 V2.0 描述下一稳定性补丁的目标；产品当前仍是 1.0.0 基线，不能因文档升级而视为已交付。

### PRD-003 [P1] 隐私描述混淆“记录”与本地存档

V1 一处禁止记录密码，另一处要求把游戏输入写入 localStorage。V2 规定：允许为恢复游戏而在本机保存玩笑密码；禁止上传、遥测、日志记录或分享原文。

### PRD-004 [P1] Unicode 定义错误地把所有 emoji 视作一个字符

单个 Unicode 码点与用户感知字素并不等价。例如带肤色修饰的 emoji 和 ZWJ 组合通常包含多个码点。V2 保留现有“按码点计数”的产品决定，并明确不按字素簇计数。

### PRD-005 [P1] 部分验收前置条件不足或不可触发

`AC-007` 的示例可能同时让长度规则失败；`AC-017` 已写“所有规则通过”后再要求“达到最终条件”，无法验证最后一步。V2 使用确定输入和“一项未满足”的前置状态。

### PRD-006 [P1] 参考解缺少分阶段上下文

最终参考解的数字和为 42，不能在新局直接越过第 04 条的数字和 25。V2 增加真实路径：先用数字和 25 的中间密码解锁验证码和第 13 条，再切换为最终参考解。

### PRD-007 [P2] 状态示例验证码不在合法字符集

V1 示例 `ABCDE` 包含被排除的 `B`。V2 使用合法示例并要求按字符集校验。

### PRD-008 [P1] 存档缺少 schema 版本、迁移和不变量

V1 没有说明如何兼容旧 key、如何处理未来未知版本、如何保留合法历史解锁。V2 增加 `schemaVersion`、`rulesetVersion`、旧格式迁移、严格字段校验和未知新版不覆盖策略。

### PRD-009 [P1] 保存失败验收允许静默丢进度

V1 `AC-022` 只要求“不白屏”，与“不得无提示丢失进度”冲突。V2 要求持续可见且可访问的失败状态，并验证恢复保存后的清除行为。

### PRD-010 [P2] 性能目标不可量测

V1 使用主观“低于 100ms”且没有测试环境、样本与统计口径。V2 规定 21 条固定规则、指定输入样本、事件到下一绘制帧的 p95，以及记录浏览器和设备环境。

### PRD-011 [P2] 离线能力表述超过现状

当前存在 Manifest，但没有 Service Worker。已经加载的页面断网后可能继续运行，不代表断网刷新或重开仍可用。V2 明确不宣称 PWA 离线启动能力。

### PRD-012 [P2] CSP 要求忽略托管平台能力

静态文件仓库不能保证所有托管平台均可设置响应头。V2 要求在可控主机配置响应头；不可控平台保持资源同源并在发布记录中说明限制。

## 4. 已验证的通关事实

1. 新局先输入中间密码，使数字和为 25，推进至验证码。
2. 正确提交验证码后推进至第 13 条，第 04 条被合法废止。
3. 将输入替换为最终参考解，推进至压力阀。
4. 在每次点击间隔不超过 1150ms 的条件下点击压力阀 10 次。
5. 在固定 5x5 棋盘点击 `c3`；参考解已经包含小写 `c3`。
6. 最终 21/21 通关；最终输入为 42 个 Unicode 码点，ASCII 数字和为 42。
7. 刷新后可恢复正常胜利状态。

最终参考解：

```text
mangoIVAu喵🐱春c3🔥💀987654xyzkxyzkxyzkxyzqwx!?
```

该字符串是最终状态测试夹具，不是“从空白新局直接粘贴即可通关”的作弊码。

## 5. 发布建议

### 必须先完成

1. 修复 CODE-001 至 CODE-005。
2. 为五项修复补充可重复的浏览器 E2E。
3. 运行规则单测、完整通关 E2E、存档迁移 E2E。
4. 在 Windows Edge/Chrome 上人工验证至少一种中文 IME；在 iOS Safari 或等价真机环境验证输入和 320px 主流程。

### 可进入同一补丁

1. 修复减少动效、公告优先级和验证码文案。
2. 补充结果页 Escape/焦点返回行为。
3. 明确 Manifest 不代表离线 PWA。

## 6. 评审限制

- 未对所有目标浏览器完成真机矩阵。
- 320px 下已检查胜利弹窗按钮可见，但没有完成移动端全流程；页面测得内容宽度大于视口，因 `overflow-x: hidden` 无法据此单独认定存在阻断式横向滚动。
- 未进行第三方安全渗透测试；本产品为纯前端游戏，验证码不是安全机制。
- 工作树包含评审前已有的资源整理改动，本报告不评价这些改动的来源，也未回滚。
