## 1. 执行摘要

本轮按 `PRD_V2.0.md` 对现有 Password Panic 做了稳定性补丁，重点处理五类原有风险：

1. 不可信存档可制造假胜利并锁死输入。
2. 旧会话的延迟胜利回调可跨越重开。
3. IME 合成态 Enter 被游戏拦截并导致失焦。
4. 140 字符限制混用 UTF-16 码元与 Unicode 码点。
5. `localStorage` 写入失败时进度丢失却没有持续提示。

同时补充了损坏存档备份、未来版本存档保护、保存恢复后的提示清除、回归公告优先级、验证码大小写一致、减少动效、胜利弹窗 Escape/焦点恢复和分享隐私回归。

### 3.2 存档契约

- `STATE_SCHEMA_VERSION = 2`。
- `RULESET_VERSION = "1"`。
- `MAX_PASSWORD_POINTS = 140`。
- `parseStoredState()` 显式返回 `fresh`、`migrated`、`restored`、`corrupt` 或 `incompatible`。
- 无 schema 的合法 V1 记录通过显式迁移升级，不根据当前输入收回合法历史解锁。
- 布尔字段只接受 JSON 布尔值；字符串、数字和对象不再被宽松转换。
- 时间字段要求安全、有限、非负值。
- 验证码只保留合法字符集；非法值回退为本次新生成验证码。
- 损坏 JSON 原样备份到 `password-panic-state-corrupt-backup`，再建立新局。
- 高于支持范围的 schema 或未知规则集不自动覆盖，显示不兼容状态，并允许用户明确点击“开始新局”。
- 恢复时根据 21 条规则和三个互动标记重算胜利，不信任存档中的 `victory`。
- 密码恢复和输入截断均按 Unicode 码点处理，去除 CR/LF 和孤立代理项。

### 3.3 异步与重开隔离

- 引入 `sessionGeneration`，延迟胜利、恢复弹窗、聚焦、规则动画、Toast、互动提示和复制反馈在执行前校验当前会话。
- 重开时清理可清理的 timeout、压力计时器、弹窗和滚动锁。
- `showVictory()` 再次检查会话代次和 `state.victory`。
- 保存失败状态持续显示；后续保存成功后清除。

### 3.4 输入与交互

- 移除 textarea 的固定 `maxlength="140"`，避免把 UTF-16 码元上限误当作码点上限。
- 输入和恢复都在 140 码点处安全截断，不拆分非 BMP emoji。
- IME 合成态 Enter 不 `preventDefault()`、不失焦；`compositionend` 后再执行校验。
- 验证码提交去空白并转大写，界面明确“不区分大小写”。
- 同次输入同时发生新规则通过和旧规则回归时，公告优先说明回归。
- 减少动效模式下不执行 CAPTCHA WAAPI 摇晃和胜利彩带。

### 3.5 胜利、分享与可访问性

- 胜利弹窗仅在全部规则通过或合法废止后打开。
- Escape 关闭胜利弹窗，焦点返回结果重开入口；弹窗可再次打开。
- 剪贴板失败显示可见 Toast，不改变胜利状态。
- 分享文本不包含游戏输入、验证码或内部 schema 字段。
- 存储状态使用 `aria-live`；主要按钮具有可访问名称；结果对话框使用 `aria-modal`。

### 3.6 事实边界

- 本轮没有修改 21 条规则的产品设计、ID、顺序、废止关系或参考解。
- 本轮没有增加后端、账号、排行榜、云同步、遥测或第三方运行时框架。
- 本轮发布提交、`v2.0.0` 标签与 GitHub Release 使用同一源码版本。
- `package.json` 与 `package-lock.json` 的产品版本均已升级为 `2.0.0`。

### 4.3 测试自身的不稳定项

实施期间曾出现一次 E2E `16/17`，失败用例为：

```text
a delayed victory from the previous session cannot cross a reset
```

调查结论：测试使用真实点击重开时，420ms 胜利延迟已经合法打开弹窗，遮罩层拦截了第二次点击。该问题属于测试时序设计，不是产品 session 隔离回归。

处理方式：同一页面内同步触发两次 `reset.click()`，再等待 700ms 验证旧回调不能作用于新局。产品侧 session 防护未被削弱，修正后全量测试稳定通过。

### 4.4 320px 横向布局

初始测得根文档：

```json
{"viewport":320,"scrollWidth":334,"left":10.018783569335938,"right":309.981185913085938}
```

加入根文档横向裁剪约束后，最终两条几何证据为：

```json
{"viewport":320,"scrollWidth":320,"left":10.0137939453125,"right":309.9862060546875}
{"viewport":320,"scrollWidth":320,"left":29,"right":291}
```

注意：`overflow-x: clip` 会使根文档 `scrollWidth` 不再代表所有被裁剪的内容。因此本报告只确认已检查的胜利卡片和“开始新局”按钮位于 320px 视口内，不把该结果扩大为“所有元素在 320px 均无隐藏溢出”。

## 12. 剩余风险与未执行项

### 12.1 未覆盖风险项与发布披露

1. **跨浏览器未验证**：只执行 Edge 155；PRD 还要求 Chrome、Firefox、Safari/WebKit 和 Android 环境。
2. **真实移动设备未验证**：没有 iOS Safari、Android Chrome 或触摸设备真机执行记录。
3. **真实输入法未验证**：IME 测试是合成事件，不代表中文/日文输入法候选窗口和组合文本在真实系统上的行为。
4. **完整可访问性未验证**：没有屏幕阅读器、200% 缩放、完整键盘陷阱和焦点顺序报告。

### 12.2 非阻断但需记录

1. 性能只测同步 handler，不能替代 NFR-PERF-001 的帧级 p95。
2. 320px 只检查两个关键几何位置，根文档 `overflow-x: clip` 可能隐藏其他未被逐项检查的内容。
3. E2E 硬编码 Edge 安装路径 `C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe`，不利于直接迁移到 CI。
4. 未执行 CSP/静态托管响应头检查；PRD 对不可控托管平台已有能力边界说明。
5. 未执行第三方安全渗透测试；验证码本来就不是安全边界。
6. 未接入分析、后端、云同步或账号能力，符合当前非目标。

### 12.3 建议后续验收顺序

1. 在 Windows Chrome 和 Firefox 运行同一 E2E 主路径。
2. 在 Android Chrome 与 iOS Safari（或可用 WebKit + 真机）验证 320px、触摸和 IME。
3. 用 NVDA/VoiceOver 检查规则动态更新、存储错误、验证码和胜利对话框。
4. 浏览器放大 200% 检查主要按钮、错误提示和结果页面。
5. 把性能测试改为 `requestAnimationFrame` 或 PerformanceObserver 统计“事件到下一绘制帧”。
6. 后续补丁继续保留 PRD 实现状态与实际测试证据同步。

本轮 V2.0 稳定性补丁在 Edge 155、Windows 10 环境下完成了规则、状态契约、真实通关、迁移、异常存档、IME 合成、Unicode 边界、异步隔离、保存失败、减少动效、分享隐私、基础可访问性和同步输入性能的自动化验证。

因此建议：

- **按用户明确要求发布 `v2.0.0`**：允许，必须同时披露测试边界。
- **全平台 V2.0 兼容性声明**：不允许；后续补齐跨浏览器、移动真机、真实 IME、屏幕阅读器、200% 缩放和帧级性能矩阵后才能声明。
